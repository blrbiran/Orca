# Task Results Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show task and deterministic group results, captured during original execution, with honest partial/missing states and snapshot-bound outputs.

**Architecture:** ccloop accepts optional metadata and captures immutable attempt observations in isolated private namespaces. Two read-only optional control methods transfer labelled evidence independently of core execution; Orca admits it in a bounded fenced collector and serves immutable result DTOs/output previews. Safe React result surfaces consume these facts without new model calls or command writes.

**Tech Stack:** Existing TypeScript/Zod/Node filesystem and child process, SQLite/Express/React/i18next/Vitest. No new dependency/schema migration.

**Spec:** `docs/superpowers/specs/2026-10-10-task-results-design.md`; effective §8 overrides old handoff transport. Related Progress spec and its §8 apply to shared detail.

## Global Constraints

- No separate summarizer/model invocation, historical backfill or log inference. Task+group aggregate; saved partial results; missing/malformed explanation does not change real execution/verification/usage/attempts.
- `task-result-v1`: goal ≤4000 chars; completedWork/conclusions/limitations each ≤32 text entries ≤4000 chars; outputs ≤32 with path ≤1024 and label ≤256; total report UTF-8 JSON ≤65536 bytes. Invalid path is output unavailable, not task failure.
- Capture ≤64 files/attempt, ≤1048576 bytes/file; text preview ≤131072 bytes. Relative safe POSIX paths, no traversal/URLs/drive/NUL/backslash/symlink/special file or changed-during-read acceptance. Inert text/Markdown; no unsafe HTML/remote assets.
- Dedicated `control/task-result-evidence` and `run/task-result-captures`, controller-fenced 0700/0600, excluded from all acceptance-critical archives/continuation closure. Core protocol/candidate/collect/capabilities/handoff shapes unchanged.
- New optional control methods `task-results` `{input,afterRevision}` and `read-task-result-evidence` `{input,manifestRef,ref}`, accepted-envelope and index/manifest membership authority. Live no-candidate reads; ≤64 observation refs/page; immutable execution snapshot, higher-revision verifier successors, per-attempt actual verification states.
- Optional RPC timeout 1000 ms; one job/run, global concurrency two; core bookkeeping/transitions independent; late writes fenced. Unsupported cache only actual old command refusal and executable file identity, invalidated on changed binary. Cursor advances after complete admitted page; no stale rollback.
- Keep fixed ab824d1 package/lock/default pin. ccloop feature source /private/tmp/orca-results-ccloop-20261010 branch codex/task-result-channel-20261010; paired tests exact absolute feature build. Installed report production needs later human publication+repin; local override is not release proof.
- Owned test roots, no CCMEM_CONFIG_PATH, no paid provider or production runtime/data switch. New tests first; raw logs/RCs; mutations only cloned committed source, restore working/cached diff0. No source main merge/push/deletion.
- One implementer at a time, no worker-created agents. Task reports/evidence and controller rulings appended; final human audit per user, no interim approval pauses.

## Review Focus

- Decorated-final metadata answer-like keys/depth must not become a second answer or poison serialization: Task 1.
- Metadata capture/reading failures must not re-enter core checkpoint/continuation closure: Tasks 2/3.
- Execute-visible-before-verify, prior rejected attempt while new one runs and immutable verifier evolution: Tasks 2/3/4.
- Cleanup/shutdown racing optional retention cannot claim saved bytes or write late: Task 3.
- Cross-owner snapshot/hash/path access and stale report reuse must refuse without losing truthful task state: Tasks 4/5.
