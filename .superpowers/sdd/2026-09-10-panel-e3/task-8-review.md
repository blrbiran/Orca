## Issues

### Critical (Must Fix)

None found.

### Important (Should Fix)

- **`web/src/DecisionList.tsx:14` (diff line 567) — React list key can collide.** The key is `` `${row.projectKey}::${row.id}` ``. `projectKey` is an arbitrary, unrestricted string from `--repo <projectKey>=<path>` (`src/panel/server.ts:68`, split only on the first `=`, no character restriction), and `id` is likewise an arbitrary ledger-supplied string. Two rows such as `{projectKey: "a::b", id: "c"}` and `{projectKey: "a", id: "b::c"}` produce the identical key `"a::b::c"`, which React would treat as the same node — silently misrendering or dropping one of two genuinely distinct decisions on any list update. This is exactly the collision class `src/panel/coverage.ts:12-17`'s own `keyOf` explicitly rejects a naive separator for ("`A space-joined key would collide whenever either half itself contains a space; neither projectKey nor a decision id is guaranteed free of one`" — the same reasoning applies to `::`). Fix: use a collision-safe key, e.g. `JSON.stringify([row.projectKey, row.id])`, or simply `row.id` combined with array index as a tiebreaker, rather than a printable separator that can appear in either field.
