The capsule therefore claims a source base that was not used to create the execution workspace; using it for restore/reconciliation can misattribute the saved result, and refusing it later unnecessarily loses recoverable work.

   Fix by freezing the resolved original base before workspace materialization and carrying the exact identity actually used into capture, with the appropriate explicit relationship for continuation workspaces. Do not repair this by re-resolving the current target ref at capture/recovery time, or by universally equating continuation HEAD with original base. The stored evidence cannot reproduce the original mode semantics or detect their alteration as required by §2 and the later protected-input checks.

   Either retain and validate the supported full permission semantics or explicitly refuse nonzero `0o7000` modes before publishing a complete capsule. Conservative refusal fits the existing producer scope. Cover directory setgid/sticky as well as file special bits.
