## Required amendment: preserve the entire protocol-3 collection boundary

**P1; Tasks 3, 5, 6, 7.** Task5's interface says “Expose capsule in collected evidence without changing old report bytes when absent.” Preserving the absent case is insufficient: a finite protocol-3 run can produce a new capsule, and an old Orca consumer must still collect that failed run. Both producer and consumer validate the collection and terminal object strictly: ccloop `src/control/command.ts:130`, `:140`, `:236`; Orca `src/control/ccloopPort.ts:31`, `:34`. A newly added capsule field is rejected. The producer also returns the persisted terminal state directly (`src/control/collect.ts:86`), so adding durable mode/entry metadata to shared state in Task6 can leak the same incompatibility through terminal fields.

**Task amendment:** Replace Task5's quoted interface with a separate strict recovery-evidence read channel, for example `saved-result-evidence` and `read-saved-result-evidence`. Bind both to the accepted source/run/attempt identity; bind child reads to a validated capsule manifest and reachable ref. Keep v3 `collect`, terminal projection, capabilities/list/resolve, and accepted/hash bytes unchanged even when a capsule exists. Internal recovery state may grow, but the v3 projection must explicitly retain its old wire shape. Define any v4 collection/state shape separately. Task5 can implement the new methods unadvertised; advertise `features.savedResultRecovery='v1'` only when Task6 implements the complete promised feature. Task7 negotiates that feature, recursively validates/archives the new channel's references under existing ownership and read permissions, and handles unsupported peers without altering ordinary collection.

**Required criteria:** Run a finite v3 format-failure fixture that actually creates a capsule through the new producer, then parse its collection with the unchanged old consumer and compare its expected old response shape/bytes. Separately prove the new channel returns the capsule, refuses foreign/non-reachable refs, and archives all required nested evidence. Exercise v3 collection after internal state gains the new durable fields. A mutation that inserts capsule or recovery metadata into the v3 response must fail the compatibility criterion. This follows the approved compatibility boundary; it does not reopen normalization or recovery eligibility decisions.

## Task8 coverage amendment: initial import needs the same primary selection

**P2; Task8.** The layer decision-table tests alone do not cover the initial import producer. Current `src/control/planImport.ts:203` calls `estimatorSlotFor(..., {}, profile)` and explicitly resolves before reading plan source; `:415` uses that preparation in the production async importer. `estimatorSlotFor` and the transaction's `currentEstimatorPartial` currently have no archived-plan worker layer. Re-estimate callers likewise pass overrides rather than the full effective worker input. Changing `slotLayers` in isolation can therefore make direct/group-preview tests pass while an imported plan whose primary is B still probes/freezes operator A as its estimator. The approved spec preserves plan-below-panel inheritance and makes the estimator follow the effective group primary when no concrete role override exists.

**Task amendment:** Explicitly carry the relevant plan worker layer into initial import, re-estimate, and their post-await authority rechecks, alongside existing panel/operator layers. Add production async-import and re-estimate criteria for operator A + plan primary B/B-m + no role override, and for a historical operator model-only A-m override retaining A. Verify frozen estimator selection and provenance, the actual probed partial, and refusal on a plan/layer race. Retain the no-estimate path with unavailable estimator and no alternate-Agent probe. Record the exact superseded import-time “operator only” test expectations if changed. This is an integration/coverage correction to Task8, not a new inheritance rule.

## Task9 coverage amendment: crash recovery must recover the lock too

**P2; Task9, consumed by Task10.** The plan specifies a shared exclusive table lock and crash recovery of intent/receipt, but its crash bullets do not require a second real process to acquire the lock after the original holder dies. A durable directory/file lock can strand the operation before receipt recovery runs; an age-only lock breaker can instead admit two live writers. Both outcomes defeat the approved two-process/CAS and crash-replay guarantees.

**Task amendment:** Define the lock lifetime/recovery primitive before implementation: an OS lock released on process death, or a private ownership record with verified dead-owner reclamation. Never reclaim solely because a timeout elapsed or delete another operation's evidence. In the named before-rename and after-rename/before-receipt windows, actually terminate the holder process and replay the same operation from a fresh process. Assert bounded reacquisition, same operation/digest/receipt, unchanged mode/custom fields, and no double mutation. Also hold the first process alive through a slow probe and prove the second cannot steal its lock. This adds an observable crash criterion to the already approved design.
