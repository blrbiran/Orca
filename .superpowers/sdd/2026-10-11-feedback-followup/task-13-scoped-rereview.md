## New Important findings in this fix diff

**A. Ccloop loop attempt was conflated with Orca provider dispatch ordinal.** The new equality `capsule.attempt !== run.providerAttemptOrdinal` (`src/panel/runDiagnosis.ts:37-38`) is unsound. Orca increments `providerAttemptOrdinal` once when reserving an external dispatch (`src/control/executionDriver.ts:247`; `src/control/webDispatch.ts:544-549`). Ccloop loops inside that dispatch, sets `attempt = state.attemptsUsed + 1`, and captures the format failure with that internal attempt (`/Users/biran/code/skills/loop/ccloop/src/controller/runLoop.ts:1399-1444,2117-2119`). A first Orca dispatch can therefore have ordinal 1 while a real ccloop failure capsule has attempt 2 after an earlier internal attempt. The collection persists the producer attempt directly as `savedSource.attempt` (`src/control/executionDriver.ts:541-549`). This new equality turns a valid typed failure into `unknown` and omits its saved final/decode refs from the manifest (`src/panel/runDiagnosis.ts:46,50-54`; `src/panel/controlViews.ts:1065`). Keep the capsule-to-saved-source attempt check; do not equate this counter with Orca dispatch ordinal. Add a test with dispatch ordinal 1 and capsule/source attempt 2.

**B. The new `valid <= candidates` invariant rejects a genuine ambiguous normalization.** `src/panel/runDiagnosis.ts:25-26` treats `candidates` as a bound on `valid`, but the producer scanner counts distinct top-level parsed spans as candidates and accepted answer-shaped **nodes** as valid (`/Users/biran/code/skills/loop/ccloop/src/runtime/codex/protocol.ts:184-191,250-261`). One top-level JSON wrapper can contain two distinct valid execution answers: read-only invocation of the paired `normalizeExecutionFinal` with `{first: completeExecution, second: partialExecution}` returned `{"status":"unavailable","reason":"execution-format-ambiguous-or-hidden","diagnostic":{"method":"none","candidates":1,"valid":2,"hidden":false,"originalBytes":242}}`. That is a typed actual ambiguous failure, yet the new schema rejects it, again suppressing cause and saved refs (`src/panel/runDiagnosis.ts:39-46`; `src/panel/controlViews.ts:1065`). Remove the cross-unit inequality and retain the strict field types plus the reason rule; test this exact producer output. The fix’s malformed-normalization test covers a contradictory reason, not this valid case (`tests/panel/runDiagnosis.test.ts:32-40`).
