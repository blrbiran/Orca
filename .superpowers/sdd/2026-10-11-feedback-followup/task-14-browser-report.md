## Harness incidents and limits

The first panel launch inside the command sandbox failed because `openControlStore` invokes `ps -p` to establish its writer lock (`spawnSync ps EPERM`). The same temp-root launcher succeeded through approved escalated execution. A second launch refused a plan outside its trusted repo (`control-path-escape`); moving the synthetic plan into `atlas/plan.json` resolved it. These were harness setup failures.

An early restart with `PATH=/usr/bin:/bin` removed `node` from the fake ccloop child environment, producing `control-peer-exit:127:env: node: No such file or directory` on the run. That run is retained under `/private/tmp/orca-task14-browser-20261012` and excluded from clean Results conclusions. On that restart, the first task-control view briefly displayed `control-internal-error · HTTP 500 · The control read could not be completed` after an epoch reset; opening the group again succeeded. The exact failing request was not captured and server stderr contained no corresponding stack. A fresh root with a temporary `bin/node` symlink did not reproduce the 500; this is an unresolved single observation, not an established product regression.

The clean fixture is `/private/tmp/orca-task14-browser-clean-20261012`; its launcher is `/private/tmp/task14_browser_panel.py`. The clean fake worker wrote `fake-marker.json.calls` containing `plan`, `execute`, `verify`, plus a saved-result capture index at revision 3. After a stalled IAB download-event wait interrupted the browser turn, CUA in this subagent reported no available IAB browser. The controller's IAB session remained available. It reopened the same fixture at a fresh loopback port, logged in as the seeded owner, opened the group's Results tab, previewed `answer.txt`, clicked its Download control, then used a separate authenticated Node fetch against `/api/control/runs/<run>/results/outputs/<output>?download=1` to verify the exact response above. It reopened the fixture again, switched through the login UI to the seeded member, and observed owner installation controls absent from Global Settings. The auxiliary three-state `buildApi` fixture rendered an overview but did not expose a task-control surface, so it is excluded from browser Results claims. No additional Task 11 parked-unknown UI claim is made here.
